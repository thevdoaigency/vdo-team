Internal — Leopardo Efficiency

Footage ingest through library serving. The full content pipeline.

One shoot's path from LucidLink to a reusable, request-ready library asset. Five stages. Nothing skipped, nothing tracked that doesn't need to be.

01

Ingest

Footage lands on LucidLink inside a new project folder, named YYMMDD_COMPANY_PROJECT — for example 260630_LEOPARDO_EFFICIENCY_CHICAGO. The full twelve-part template is created day one: projects, field media, GFX, SFX, music, exports, documents, tools, VO, AI gen, code, acquired media. Nothing in this folder is indexed. It doesn't need to be found by a system — it needs to be found by whoever's editing it, and the naming convention already does that job.

02

Project — marketing deliverables

Editors work the shoot's Premiere project inside 00_PROJECTS. This is where the actual client work gets cut — case studies, social pieces, client-facing edits. Finished output lands in 06_EXPORTS. This tier is working output: versioned, sometimes messy, v1 through v10. It stays that way. It is never tracked, because tracking a folder that's mid-process just teaches people not to trust the index.

03

Library project

Once a piece has actually shipped — posted as a finished deliverable on Monday — it gets rebuilt into a separate, clean Premiere project: 260713_Leopardo Efficiency_LIBRARY. Sequences are duplicated in, text and music stripped, and exported as clean masters. Full interviews get their own sequence, trimmed to the subject's answers only — no off-camera questions, no dead air. Every export produces an XML/JSON pair alongside it.

STAGING: DELIVERABLES/ · INTERVIEWS/ · XML_JSON_PAIRS/

04

Archive

Once a project's finished assets are promoted, the original shoot folder — raw field media, the working Premiere project, everything — comes off LucidLink and moves to Backblaze B2. This tier is cold by design: cheap at rest, rarely opened, and only pulled back down if a project needs to be revisited. Wipes are triggered by LucidLink storage pressure, not by a calendar.

05

R2 · Monday · local bridge · GX10

Promoted masters move from local staging into Cloudflare R2 — the library's permanent, request-ready home. Monday logs one row per asset: project, type, R2 key. A request comes in through Leopardo Efficiency's local bridge interface, sitting behind Cloudflare Access — getting through that gate is the authorization, nothing further is checked per-asset. GX10 holds a scoped, read-only R2 credential limited to Leopardo Efficiency's prefix, pulls the asset directly, caches it just long enough to render, and discards the copy.

Phase 2

This pipeline is built once, for Leopardo Efficiency, by hand. Once proven, it repeats — its own local bridge interface, its own Cloudflare Access gate and allow list, its own Monday board, its own R2 prefix and scoped GX10 credential — for each of the remaining six portfolio companies. Same shape, six more lanes.
